# 压测记录 — add-webui-console（任务 3.5 / 3.6）

日期：2026-09-08 · 环境：Linux 6.x，tmpfs 日志盘，debug 构建二进制
方法：`cargo run -p xtask -- stress`（xtask 压测工具，驱动真实 `xkeeper webui` 二进制端到端验证；数字来自 src/web.rs 进程内压测与 xtask 两轮运行，结论一致）

生成器：`sh -c 'timeout 300 sh -c "while :; do dd if=/dev/zero bs=1M count=1 2>/dev/null; sleep 0.09; done" | tr "\0" "x" | fold -w 31'`
（≈10MB/s 持续输出，每行 32 字节；`log_max_size = "0"`，`autorestart = "never"`）

## 实测数字

### 相位 1：正常客户端（全速消费，3 秒）

| 指标 | 数值 |
|---|---|
| 送达行数 | 991,232 行 / 3s |
| WS 日志帧数 | 484 帧（单帧上限 64KiB+1 行） |
| 帧行聚合比 | 1 : 2048 |
| 落盘吞吐 | 9.9 MB/s |
| 守护进程 RSS | 20,864 → 26,860 KiB（+5.9 MiB，有界） |
| 守护进程 CPU | 1.3%（按全机逻辑核归一） |

### 相位 2：慢速客户端（1 帧/100ms ≈ 0.6MB/s 消费 6s，随后全速追赶 3s）

| 指标 | 数值 |
|---|---|
| 送达行数（慢+追赶） | 1,973,120 |
| Gap 标记 | 904,704 行被显式标记「跳过」 |
| 落盘吞吐 | 10.2 MB/s |
| **吞吐保持率（零反压验证）** | **104.1%**（慢客户端期间子进程吞吐不降反升，在测量噪声内） |

### 零反压结论（log-management「输出排空零反压」场景）

- (a) 子进程输出吞吐不因订阅者存在/挂起而下降：**通过**（保持率 98.8%–104.9%，多轮一致）。
- (b) 守护进程 RSS 稳定，不随总输出量增长：**通过**（约 500MB 总输出下 RSS 增长 <6MiB，
  全部为环形缓冲/批缓冲的常量上界）。
- (c) 落盘完整性：**通过**（除生成器被 kill 的尾部残行外，磁盘上每行均完整 31 字节；
  行序与内容无损）。
- (d) 慢客户端只丢自己的实时流：**通过**（丢失量以 LOG_GAP 帧显式记账送达，
  环形缓冲与落盘不受影响；正常客户端零丢失）。

## 备注

- 一帧多行的批量帧格式使 WS 帧率与行速率解耦（~500 帧/s 承载 33 万行/s）。
- Gap 触发条件：慢客户端积压超过有界订阅队列（64 批 ≈ 16MiB）——短暂卡顿
  （数百毫秒）在缓冲垫内，不会产生丢行标记；持续慢消费才触发，符合设计。
- 会话级保护：发送预算 10s，真死链最终关闭会话由客户端退避重连自愈。
