## Purpose

定义 xkeeper 守护进程内建的指标采集与暴露能力：受管子进程的 CPU/内存利用率
采样、系统资源概况、按流的日志输出速率统计（滚动窗口），及其精度、空值与
跨平台一致性要求，供控制面与 Web 控制台共享消费。

## ADDED Requirements

### Requirement: 每程序资源利用率采样

xkeeper SHALL 对每个处于运行态的受管程序周期采样 CPU 利用率与驻留内存
（RSS），采样周期 MUST 不高于 1 秒：

- `cpu_percent` SHALL 由相邻两次采样的进程 CPU 时间（用户 + 内核）增量除以
  墙钟时间增量计算，并按主机逻辑核心总数归一（100 表示占满整机全部核心），
  有效范围 0..=100，保留一位小数精度；
- `mem_bytes` SHALL 为采样时刻的进程 RSS 字节数；
- 程序未运行或尚无 pid 时，两个指标 SHALL 为空（null）而非 0；
- 程序重启导致 pid 变化后，SHALL 以新 pid 重新建立采样基线，不出现跨进程
  混算的伪值。

#### Scenario: 运行中程序有指标

- **WHEN** 某程序处于 running 且已运行超过一个采样周期
- **THEN** 其状态投影含非空 cpu_percent（0..=100）与非空 mem_bytes

#### Scenario: 未运行程序指标为空

- **WHEN** 某程序已声明但从未启动，或已退出且不重启
- **THEN** 其状态投影中 cpu_percent 与 mem_bytes 为 null，不显示为 0

#### Scenario: 重启后基线重建

- **WHEN** 某程序崩溃退出并由守护循环以新 pid 重启
- **THEN** 新进程第一次采样完成前 cpu_percent 为空，其后数值只反映新进程

#### Scenario: 采样竞态不致错

- **WHEN** 某程序在两次采样之间退出，采样读到失效 pid
- **THEN** 该程序指标安静地降级为空值，守护进程不报错、不中断采样线程

### Requirement: 系统资源概况

守护进程 SHALL 周期采样主机系统级指标并随概况暴露：系统 CPU 利用率
（与每程序口径一致，按逻辑核心归一，0..=100）与内存概况（已用字节、总量
字节）。采样周期与每程序采样同节奏。

#### Scenario: 概况含系统指标

- **WHEN** 守护进程运行中且状态被查询
- **THEN** 概况中含系统 cpu_percent、内存已用与总量字段，且数值随时间
  反映主机负载变化

### Requirement: 日志输出速率统计

xkeeper SHALL 为每个程序的每个输出流（stdout/stderr）统计日志输出行数：

- 统计 SHALL 以每秒为粒度维护滚动计数，保留最近至少 300 秒；
- 对 1s、10s、60s、300s 四种窗口，SHALL 能给出该窗口内的平均行速率
  （行/秒）；
- 统计 MUST 在日志采集路径上进行，与是否存在日志查看者（CLI follow、
  Web 订阅）无关；
- 程序重启后各流计数 SHALL 清零重新累计。

#### Scenario: 稳定输出速率可查

- **WHEN** 某程序以约 5 行/秒稳定向 stdout 输出持续超过 10 秒
- **THEN** 其 stdout 的 10s 窗口速率接近 5 行/秒，1s 窗口围绕 5 波动

#### Scenario: 无查看者仍计数

- **WHEN** 没有任何客户端订阅或 follow 该程序的日志
- **THEN** 其行速率统计照常累计，随后订阅时能立即读到当前速率

#### Scenario: 重启后计数清零

- **WHEN** 程序重启（无论崩溃或手动）
- **THEN** 重启前的高速率不带入新进程的速率统计

### Requirement: 采样零干扰

指标采集 MUST NOT 以任何方式影响受管进程自身的执行：

- 采集 SHALL 仅通过只读系统接口进行：Linux 读取 procfs，Windows 以
  `PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_VM_READ` 级别打开进程
  句柄；MUST NOT 发送信号、挂起/恢复进程、附加调试器或请求任何可改变
  子进程状态的权限；
- 采集 MUST NOT 派生子进程或向子进程的管道写入任何字节；
- 指标线程发生 panic 或异常退出时，守护循环与全部受管程序 MUST 继续
  正常运行，仅指标字段降级为空；
- 采集线程 MUST NOT 持有守护循环状态锁跨越采样系统调用（不得因采样
  延迟重启/停止等命令的执行）。

#### Scenario: 采集不触碰子进程

- **WHEN** 指标采样持续运行且子进程正常执行
- **THEN** 守护进程对子进程不存在任何信号、挂起、调试附加或句柄写操作，
  子进程行为与不被守护观察时一致

#### Scenario: 指标线程崩溃不影响守护

- **WHEN** 指标采样线程 panic 退出
- **THEN** 受管程序照常运行与重启，状态投影除指标为空外一切正常

#### Scenario: 采样不延迟控制命令

- **WHEN** 某程序处于退避等待且指标线程正在采样周期内
- **THEN** 到期重启的发起不被采样阻塞（采样不持锁跨系统调用）

### Requirement: 跨平台一致

指标采集 SHALL 在 Linux 与 Windows 上提供相同的字段、量纲与空值语义；
采集 MUST 通过操作系统原生接口完成（如 Linux 的 procfs、Windows 的系统
调用），MUST NOT 为采集派生子进程或引入重量级依赖。

#### Scenario: 两平台字段一致

- **WHEN** 同一配置的程序分别在 Linux 与 Windows 上被守护并查询状态
- **THEN** 投影中的指标字段名、类型、量纲与空值语义完全一致
