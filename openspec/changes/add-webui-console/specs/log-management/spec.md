## ADDED Requirements

### Requirement: 输出排空零反压

xkeeper 对子进程 stdout/stderr 管道的排空 MUST NOT 被下游任何环节反压：
子进程的输出写 MUST NOT 因守护进程自身的处理（落盘、轮转、环形缓冲、
订阅投递、查看者慢消费、指标采集）而阻塞超出操作系统管道固有的缓冲
行为。具体地：

- 泵线程 MUST 持续排空子进程管道；落盘与轮转中发生的文件系统操作
  MUST 有界（批量化、有上限的批量大小），不得引入无上界的阻塞窗口；
- 向订阅者（CLI follow、WS 客户端）的投递 MUST 非阻塞：订阅者消费
  不及时只允许丢弃该订阅者的投递并计数（「跳过 N 行」），MUST NOT
  使泵停止排空或延迟落盘；
- 日志文件写入失败（磁盘满、路径失效等）时，泵 MUST 降级为仅内存
  （环形缓冲）并继续排空管道，MUST NOT 因写盘失败反压子进程；
- 守护进程为日志路径占用的内存在任意输出速率与总输出量下 MUST 有界
  （环形缓冲容量、攒批缓冲、订阅通道均必须有上界）。

#### Scenario: 高速输出不阻塞子进程

- **WHEN** 子进程以 10MB/s 持续写 stdout 且守护进程同时落盘、推送给
  一个正常消费的订阅者
- **THEN** 子进程的输出吞吐不受守护进程影响（无因管道排空不及时导致
  的阻塞），守护进程内存占用保持有界

#### Scenario: 慢订阅者不反压子进程

- **WHEN** 某订阅者停止消费（如浏览器挂起）而子进程持续高速输出
- **THEN** 该订阅者的投递被丢弃并计数，子进程输出与落盘节奏不受任何
  影响

#### Scenario: 磁盘失败降级不反压

- **WHEN** 日志文件写入持续失败（磁盘满或路径失效）
- **THEN** 子进程继续输出不被阻塞，输出仍进入环形缓冲供 tail/follow，
  守护进程记录告警且不退出

#### Scenario: 内存有界

- **WHEN** 子进程持续高速输出远超环形缓冲容量的总日志量
- **THEN** 守护进程 RSS 稳定（仅随配置的缓冲容量变化），不随总输出量
  增长
